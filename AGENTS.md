# Development guidance

Read README.md, docs/architecture/decisions.md and docs/product/requirements.md before changing business behavior. Use the existing checkout; cloud tasks are isolated, so create no worktree unless requested.

- API and web are separate Laravel applications; web must not query API database directly.
- Add modules through explicit provider/feature registries. Flags never replace backend authorization.
- Keep domain invariants out of Blade/Flutter components. Use atomic design and shared visual tokens.
- Each tenant-owned endpoint needs cross-tenant and denied-permission tests before activation.
- Do not invent decisions for offline, QRIS, consignment or negative stock; consult product decisions.
- Run scripts/check; for web/API changes also start Compose and run scripts/smoke.py.
- Do not disable TLS/signature/checksum verification. Keep credentials out of source, logs and fixtures.
- Identity/catalog and initial ordering, fulfillment, batch and inventory ledger (intake/dispatch/receipt) are implemented. Stock opening/cooking and independent count/waste review are implemented on web and native Flutter; see docs/stock-control.md. Online cash POS and cashier shifts are implemented; see docs/cash-pos.md. Receipt discrepancy cases and wholesale administrative resolution plans are implemented in API/web; physical quarantine returns, explicitly agreed invoice/credits, reviewed refunds, issuer-funded retail vouchers and manually verified QRIS/transfer are implemented; automatic gateways remain unimplemented; cash-only durable offline with reviewed conflicts is now available (docs/reliability-and-offline.md). Read docs/supply-workflow.md for the exact scope.
- Run python3 scripts/smoke-identity.py for API/web identity or supply-workflow changes; it uses isolated temporary containers/database.
- All stock balance changes must use StockLedger.apply inside a transaction and increment stock_revision; do not bypass snapshot guards or independent-review authorization.
- Batch expiry search preserves assigned-store batch access (including cashier), legacy expires_on/id ordering and pagination100. Inclusive packaging-date bounds are independent; no invented warning horizon/31-day cap in this search. Separate explicit organization SOP now controls sale blocks/FEFO. with_balance includes quarantine and excludes waste-only. See docs/batch-expiry.md.
- Web receipt history preserves all-history pagination without dates; require paired WIB dates when supplied and use WibPeriod. Scope own/store is API authority, never browser cashier/scope filters; local pagination/receipt links and historical Sales snapshots only. See docs/web-receipt-history.md.
- Web ledger uses scoped Backend HTTP, exact store/batch identity and whitelist filters; signed historical piece deltas are not balances. Use Shared/Application/WibPeriod for ledger/audit/cash-report calendars; see docs/web-stock-ledger.md.
- Web audit must use scoped Backend HTTP, whitelist query filters, build local pagination, reject mismatched envelopes/rows, and escape all snapshot text. Never copy API credentials/cookies into HTML/URLs or access API DB; see docs/web-audit.md.
- Native audit is read-only and organization-wide: preserve Identity manage authorization and the existing central onboarding allowlist before applying filters. Never infer store-manager authority, include global null-organization events, or follow external pagination URLs; see docs/native-audit.md.
- Native password change uses existing Identity auth/password, never trims or persists password payloads, and clears the auth route stack after ACK or unknown response. Unknown is not success and must never auto-retry; see docs/native-password-change.md.
- Native receipt history is read-only, scoped own/store by the API, and must not replace checkout pending state. Use historical sale snapshots, paired WIB date range and local scoped pagination; see docs/native-receipt-history.md.
- Native ledger history is read-only and staff-scoped; use historical batch snapshots, signed base-piece deltas and explicit UTC occurred_at for WIB. Filtered rows are never current/running balance; source_id is not request UUID. See docs/native-stock-ledger.md.
- Native warehouse intake requires Inventory intake catalogue metadata and server preview/review_hash. Physical packs/date/batch/note have no defaults; preserve immutable UUID/path/body/review on unknown outcomes. Show reviewed addition, never replayed batch balance as current. See docs/native-warehouse-intake.md.
- Native warehouse uses scoped Fulfillment context can_process/can_dispatch, selected source ID and original order version. Remaining quota subtracts sent packs, never good receipts; do not auto-replace damage. Keep immutable nested UUID/path/body/review on unknown outcomes; see docs/native-warehouse.md.
- Native shift cash uses GET detail can_record_movement, original reviewed version and immutable UUID/path/body; can_manage alone never enables mutation. Unknown outcomes block refresh/pop/new operations; see docs/native-shift-cash.md.
- Native amendment uses recipient_actions.amend and original order ID/version. Only awaiting/rejected approvers may edit; never expand into postapproval changes/reapproval. Review hash binds order/version; reset stale drafts only after explicit user choice. See docs/native-order-amend.md.
- Native order entry must preview with authoritative server pricing, then submit its immutable payload/UUID/review_hash. Never infer SKU mapping by name, trust client totals, rotate an unknown submission UUID, or create auto-orders from minimum-stock warnings. Review hash is a concurrency check, not signed pricing/authorization. See docs/native-order-entry.md.
- Native recipient order decisions/receipts use GET detail recipient_actions; never infer authorization from legacy can_approve, local role alone or status alone. Receipts require every shipment line, explicit good/damaged packs (including zero), condition notes for discrepancies and original order version. Retain immutable nested UUID/path/body on uncertain response; see docs/native-ordering.md.
- Native stock controls retain exact UUID/path/body on uncertain network outcomes while the page stays alive. Do not replace pending operations, silently advance the selected revision or bypass independent review. Refresh requires reselecting and physically checking the snapshot; see docs/stock-control.md for restart limits.
- Native minimum editing uses exact product/store detail and can_manage/version metadata, never list position/SKU name or local role alone. Explicit zero stays enabled; disable sends null. Retain immutable UUID/path/body on unknown outcomes; see docs/native-stock-minimum.md.
- Minimum-stock reads remain live projections; Reliability also records durable inbox episodes and opt-in SMTP notices, with push deferred by user; see docs/stock-minimums.md. Do not introduce automatic ordering, payment requests or default business thresholds. Configuration changes require scoped manager permission, current version, UUID and audit.
- The original cash Reporting endpoints remain cash POS only; the separate commercial report has its own cohort/authorization contract (docs/reliability-and-offline.md): use Sales CashSalesReadModel, enforce organization membership and store assignment for summary/products/export, and never mix B2B/transfer/debt/cash movements into revenue. CSV must reject over 10,000 rows and neutralize formula-like text. See docs/cash-reporting.md.
- Sales must use RetailPricing, SaleStock and ShiftBook; do not write stock/cash balances across modules directly. Pending sale intents are not reservations.
- Development uses SQLite; do not claim PostgreSQL or device-release builds are verified.

- Postapproval quantity reductions use the separate order_changes workflow, never old amend. Preserve original quote until recipient acceptance, all line IDs/snapshots, min1/no increases and zero shipments. Pending holds process/dispatch/cancel under the same locked parent; unique pending_order_id prevents duplicate pending. No stock/cash writes. Web unknown results retain immutable per-order session UUID/path/body through later denial; login/401/logout clears prior-account session. Used history migration rollback must fail; see docs/order-reapproval.md.

- Native postapproval UI uses OrderChangesController/Repository and the separate changes endpoint; never amend PUT. Server actions alone authorize display. Preserve full frozen before/after review and original version; candidate expires on refresh, ACK must match parent/change/status/version+1 then reload context. Unknown including malformed ACK/408/429 blocks refresh/pop/new actions and retains immutable nested UUID/path/body through later denial;401 follows global auth route reset. No restart queue. See docs/native-order-reapproval.md.

- Native batch expiry is read-only via existing batches API and BatchExpiryRepository, preserving assigned cashier/inactive-store access under server authority. Dates are independent inclusive packaging dates, never WibDateRange/31-day cap/default horizon; with_balance includes quarantine, excludes waste-only. Validate envelope/rows/store/page and use local pagination/applied filters, never external URLs. No POS pending edits or stock writes from the batch search. Explicit SOP controls FEFO/sale blocks separately. See docs/native-batch-expiry.md.

- Global account status uses UserAccountStatus with the same locked User as membership changes. Never reactivate self or an owner in ANY membership; multi-org identities require central admin. Reactivation requires active review org, inactive state, access_version/UUID/reason and no role/password/assignment edits. Membership/deactivation increment access_version. Preserve exact pending web path/body/review through unknown/later denial; historical ACK must be followed by GET and must not resurrect later-disabled accounts. All tokens revoked; user.reactivated is explicitly onboarding audit only. Used version migration rollback fails. See docs/account-reactivation.md.

- Audit export must share AuditHistory scope/allowlist/filter/entry mapping with reader. Require explicit timezone period <=31days; cursor bounded10001 detects >10000 and8MiB encoded rows before response; never truncate or log an export event into this read-only history. Web validates every row scope/ID/type before CSV, whitelist active filters (no page/URLs), fixed filename/private/no-store/nosniff, UTF8 BOM/fputcsv and CsvText formula protection. Do not copy API cookies/credentials/disposition. See docs/audit-export.md.

- Ledger export must share LedgerHistory staff/store/join/batch/filter/entry mapping with reader. Preserve inactive-store read, deny assigned cashier and center without membership, keep historical pack metadata and signed piece deltas (never balances). BoundedExport handles10000/8MiB before response. Web shares LedgerSearch/ExportTime/CsvDownload/CsvText, validates scope/types before CSV, keeps validated integers numeric but protects all text/formula prefixes. No stock/revision/audit/receipt writes, source links or new policies. See docs/ledger-export.md.

- Shipment discrepancies freeze confirmed receipt snapshots, never client quantities or unsent remainder. One case/shipment; separate case version, parent→shipment→case→plan locks. D-11: wholesale center owner/admin proposes, recipient partner_lead confirms/rejects; no internal resolution approval inferred. No stock/revision/order/quota/cash/invoice writes. Notes stale reviewed case versions; one unique pending plan and plan_confirmed means agreement only. Audit both organizations without onboarding allowlist expansion. Web immutable per-shipment session retry/ACK scope/version checks and401/login/logout cleanup are mandatory; used migration rollback fails. See docs/shipment-discrepancies.md.

- Replacement execution is a separate wholesale confirmed-replacement workflow, never an original dispatch quota increase. Lock order→original shipment→case→resolution→replacement→batch; use case version/UUID. Bound per original receipt line damaged+missing minus all replacement packs sent, never good receipts or unsent order remainder. Supplier/source assignment and active source/target required; receipt all lines explicit good/damaged and reason. StockLedger posts replacement_dispatch/receipt atomically with revision/case/audit/receipt. Freeze SKU/pack/batch metadata; retain original order/receipt/quarantine/finance. fulfilled only when all issue packs received good; secondary damage needs follow-up without new quota. BFF immutable per-shipment session retry, scoped ACK/rows/local pagination and401/login/logout cleanup. Used migration rollback fails. See docs/replacement-fulfillment.md and docs/product/delivery-status.md.

- Advanced wholesale revisions use order_changes.kind=revision and /revisions with read-only preview/review_hash; legacy /changes filters reduction and denies revision decisions. Shared nullable unique pending_order_id holds process/dispatch/receipt/cancel. Existing totals cannot fall below sent or increase; zero tombstones preserve historical IDs, additions get fresh frozen quotes/new IDs (same supplier, explicit pack/condition/local mapping). Recipient partner_lead may propose new local mappings; supplier only existing mappings. Counterparty roles decide, no independent-person rule; active target/source for approval. No stock/receipt/invoice writes. Source/target guards, immutable native/web review/UUID retry and local pagination remain mandatory. See docs/order-revisions.md.
- CatalogConfiguration/EffectivePrice/BundlePricing own effective-price overlap/product locks, scoped private raster images and versioned non-nested recipes. Date periods are inclusive WIB, partner wholesale tier then general then base; retail lists bulk-load metadata. Preserve all historical quote/receipt/recipe snapshots and checkout price_hash. Bundle unit piece=one package, parent pack/portion1; component quantities are base pieces from opened/ready only, StockLedger posts all components atomically, never client prices. Cashier bundle endpoint MUST whitelist retail product fields and never expose wholesale price. Image/PDF files private (PRIVATE_STORAGE_PATH), bounded bytes/MIME, no client paths/URLs; web copies no API cookies/credentials.
- Partnership contracts are center draft→published→explicit partner_lead consent/rejection; accepted content immutable, actor/time/version/terms+PDF SHA256 retained. Draft and draft audit are center-only. Download PDF as attachment/private/no-store/nosniff, paths hidden. Contract mode/data_scope does not enable consignment calculations, finance or POS ACL access. PendingMutation BFF keeps immutable body/UUID through unknown/later denial;401/login/logout clears candidate and pending prefixes. Used history migrations refuse rollback. D-01/D-03/D-08 global defaults remain open; DL-13/15/16 are implemented only through explicit per-document consent/manual verification, never inferred defaults. See docs/catalog-and-contracts.md.

- Billing owns invoices/payments/credits/consignment reports. Require explicit basis/mode/tax/discount/shipping/rounding/due date and partner consent; never infer unanswered chat suggestions as global policy. Parent order locks serialize invoices, physical returns and credit caps. One active invoice per shipment line/report; rejected proposals release claims, preserving history. Payments are human-verified allocations, not provider calls or POS drawer writes. Signed balance splits receivable/customer credit. Credits require confirmed return/credit plan, historical billed cap (returns actually received), proportional tax cap, center proposal and partner decision; good-receipt damage cannot be credited twice. Consignment needs accepted contract and sold report within good-receipt limit; never read partner POS automatically. See docs/finance-and-pos-adjustments.md.
- Sales uses VoucherBook, SaleStock/SaleReturns and ShiftBook contracts. Manual noncash needs exact verified amount/reference; no drawer credit and unique reference per org/method. Vouchers explicitly own-issuer-funded/store-product-scoped/WIB and nonreserved until payment; exact integer Proportion, stable snapshots and atomic redemption. Refund manager only, server preview/hash, original sale/version, current open shift/version, historical discounted units and original batch/component allocations. Cash refund posts current shift cash out; noncash only noncash_refunds. Return stock only quarantined, original receipt immutable. Restore quota only once after full refund if explicitly chosen. Preserve frozen requests through unknown/later denial; auth/account switch clears BFF pending/candidates. Native pending remains page-memory only. Cash reports remain cash-sale snapshots before refunds, separate from B2B/noncash/refund histories. Never claim gateway settlement, global tax/business acceptance, cross-org promo funding or PostgreSQL/device release validation.


- DL-18–20 are implemented within docs/reliability-and-offline.md. User decisions: offline cash only with conflict review; organization leaders approve their own SOP; SMTP initially, push deferred. Assets/Reliability providers and manifest are active. Never invent food lifetime, relax other tenant ACLs or claim external SMTP/real device/UAT validation.
- MFA stores encrypted secret and hashed single-use recovery; login challenge is not a token. User lock and access_version bind login, password/MFA changes and revocation. Reset queues are encrypted, link token is fragment-only, MFA still required. Never flash password/token/code.
- Offline permit is own cashier/store/shift and explicit duration, not reservation. Preserve encrypted original request/UUID across restart/account switch; never label local temporary receipt server-paid. Sync posts once or durable conflict without stock/cash writes. Manager review requires version, verified physical reconciliation, frozen quote and same original cashier current open shift. Known SOP expiry is rechecked locally and server-side. Open permits/conflicts block shift close; queue-empty declaration cannot prove another device has no unsent data.
- Assets require owner organization authority and accepted cross-org contract/recipient consent; return pending retains assignment until owner actual inspection. Ownership proof stays private; incident costs never automatically invoice. Commercial report is selected-document cohort plus current cumulative adjustments; separate seller/purchase/POS metrics, explicit evidenced net costs, unknown margin=null, 10000/8MiB private CSV.
