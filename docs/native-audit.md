# Jejak audit Flutter

Halaman web berfilter dan snapshot kini juga tersedia; lihat [panduan audit web](web-audit.md).

Irisan PRD 01-AUD dan 13-SEC: modul **Audit** menampilkan catatan perubahan organisasi pada mobile/tablet. Pilih toko dalam organisasi yang dikelola, lalu buka Audit; jika navigasi mobile penuh, gunakan **Lainnya**. Modul didaftarkan eksplisit dan dapat dimatikan dengan `--dart-define=FEATURE_AUDIT=false`. Flag dan role hint hanya mengatur navigasi; API tetap memeriksa setiap request.

Pemilik, admin dan pimpinan mitra dengan keanggotaan pengelola dapat membaca audit organisasinya. Kepala toko, gudang dan kasir tidak mendapatkan akses audit organisasi meskipun ditugaskan pada toko. Ini riwayat seluruh organisasi, **bukan filter toko**. API lama tetap memberi admin pusat tanpa keanggotaan pengelola mitra hanya aksi onboarding yang sudah diizinkan: organisasi/toko, pembuatan/deaktivasi/reaktivasi pengguna dan perubahan membership. Aksi user.reactivated ditambahkan eksplisit bersama [workflow reaktivasi](account-reactivation.md), tanpa membuka audit operasional. Filter tidak pernah memperluas allowlist tersebut atau membuka harga operasional mitra. Native menggunakan organisasi toko yang dipilih, bukan pemilih semua mitra.

Filter periode kalender WIB awal/akhir inklusif (maksimal 31 hari), aksi persis, ID objek persis dan ID pelaku. Contoh aksi: `product.updated`, `order.amended`, `sale.completed`, `inventory.intake`, `shift.closed`. Nilai objek adalah ID subjek catatan, bukan UUID operasi atau izin membuka objek modul lain. Kosongkan filter tambahan untuk semua nilai dalam periode yang dipilih. Default periode adalah hari ini WIB; ubah tanggal untuk menelusuri data lama.

Tombol **Terapkan filter** mereset halaman ke 1. Input yang belum diterapkan tidak mengubah pagination, refresh atau label filter aktif. **Sebelumnya/Berikutnya** membaca maksimal 50 baris melalui endpoint organisasi yang sama; client tidak mengikuti URL pagination eksternal. Backend tetap mendukung all-history pagination bila tidak dikirim pasangan tanggal untuk kompatibilitas web. Interval API bertimezone `[from,to)`; native menerjemahkan akhir kalender ke pukul 00:00 WIB hari berikutnya. Urutan ID menurun dipertahankan dari endpoint lama. Halaman dibaca live, bukan snapshot konsisten lintas request.

Buka **Perubahan sebelum / sesudah** untuk melihat snapshot JSON yang tersimpan. Tampilan menggunakan teks, bukan HTML atau executable. Null berarti tidak ada snapshot yang disimpan, bukan bukti nilai sebelumnya nol/kosong. Actor ditampilkan sebagai ID tanpa mengganti riwayat dengan nama master terbaru. Timestamp `occurred_at` UTC eksplisit ditampilkan WIB; raw `created_at` dan field audit lama tetap tersedia. `Diamati` adalah waktu pembacaan, bukan waktu pembaruan seluruh catatan.

Kegagalan atau denial menghapus hasil lama dan ditampilkan sebagai error, bukan riwayat kosong. Retry memakai organisasi/filter/halaman yang sama. Envelope dan setiap row diperiksa terhadap organisasi yang diminta. Tidak ada tombol mutasi audit, ekspor, penghapusan atau perubahan transaksi dari modul ini. Membaca audit tidak menciptakan catatan audit baru, mengubah stok/kas atau mengaktifkan kebijakan finansial baru.

Catatan global dengan `organization_id=null`, termasuk perubahan kata sandi, tetap di luar endpoint organisasi ini. Modul bukan tampilan seluruh aktivitas keamanan akun, bukan notifikasi/inbox, dan tidak menambah antrean offline atau pemulihan UUID lintas restart. Snapshot bisa mengandung data usaha yang memang diizinkan untuk pengelola; jangan membagikannya kepada pihak tanpa hak. Audit sumber harus tetap tidak menyimpan password/token.

Arsitektur: read service `Identity/Application/AuditHistory`, validasi HTTP pada controller yang ada dan respons private/no-store. Query selalu scoped organisasi lalu allowlist onboarding jika diperlukan, baru filter pengguna. Provider Identity yang sama dipakai tanpa migrasi/dependensi baru. Native AuditModule mempunyai DTO/filter, repository, controller, page dan molekul `AuditRecordCard`; kalender memakai core `WibDateRange`.

Validasi development mencakup izin/tenant/allowlist pusat, organisasi nonaktif, batas tengah malam WIB, exact combined filters, 51 baris (50+1), input invalid, catatan global tidak tampil, snapshot yang tidak berubah setelah GET, retry/error/wrong-organization, navigasi delapan modul dan tampilan 390px text scale 1,5 dengan keyboard serta 1200px. HTTP smoke terisolasi membaca audit penjualan tersimpan, menolak kasir/kepala toko, dan tidak membocorkan data operasional melalui onboarding pusat. Perangkat nyata, PostgreSQL/concurrency serta UAT belum diverifikasi.
